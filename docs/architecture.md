# Architecture

A tour of the parts you need to know before changing anything. It covers the invariants that are
easy to break silently — not every module.

## No backend

Ledger is a static bundle. There is no server, no account, no telemetry. Everything the app knows
lives in the browser, and everything it sends leaves only because the user asked for it: a vault
file to their own storage, or a prompt to the AI provider whose key they entered.

That shapes the whole design. Anything you add runs on the user's device, in their tab, against
their data.

## Three storage layers

```
  L1  in-memory Vault          src/model/         the single source of truth while the app runs
   ↓  debounced ~1s
  L2  encrypted IndexedDB      src/persist/       survives reload; encrypted at rest
   ↓  on change / on focus
  L3  remote vault file        src/sync/          ciphertext only; how devices meet
```

**L1 — the model.** One `Vault` object (`src/model/types.ts`). All changes go through `applyOp`
in `src/model/mutations.ts`; nothing mutates the vault directly. Reads go through the selectors in
`src/model/selectors.ts` and the analytics layer, which derive rather than store.

**L2 — local persistence.** `src/persist/autosave.ts` debounces writes into IndexedDB, encrypted
by `src/persist/crypto.ts`. A failed write returns the vault to pending rather than dropping it.

**L3 — the remote.** `src/sync/engine.ts` pushes and pulls a single encrypted file. See
[sync.md](sync.md) — it is the part most likely to break in a subtle way.

## Encryption

The master password derives a key with **Argon2id**; the vault is sealed with **AES-256-GCM**
(`src/persist/crypto.ts`). The password never leaves the device and is never stored. The key lives
in memory for the session only.

The sync layer only ever sees ciphertext. A remote — Google Drive, a file in a synced folder —
holds an opaque blob it cannot read.

One deliberate exception: the Google OAuth token in `kv['sync.gdriveToken']` is stored
unencrypted, because it must survive without the vault being unlocked. It grants access to nothing
but the ciphertext file this app created.

## Money is always integer minor units

Amounts are integers in the currency's minor unit — cents, kopiyky. Never floats.

```ts
amountMinor: -1815   // −€18.15
```

Floats reintroduce rounding drift into balances that must reconcile exactly
(`opening + Σ amounts === closing`), and reconciliation is what proves an import was read
correctly. Convert at the edges — parse and format — never in the middle.

## Vault schema and migrations

`SCHEMA_VERSION` in `src/model/types.ts` is currently **7**. Forward migrations live in
`src/persist/crypto.ts` (`migrations`, keyed by the schema they upgrade *from*) and run on decrypt,
so an old vault upgrades before anything reads it.

Two rules, both about devices that upgrade at different times:

- **Migrations must be deterministic.** Two devices migrating the same vault independently must
  produce identical records — ids included, minted from fixed constants rather than randomly.
  Otherwise the merge sees two different records where there is one.
- **An additive optional field needs no bump.** Field-level merge handles it. Bump the schema only
  when the shape of existing data changes.

## Import

`src/import/` turns a bank file into rows. The flow:

```
peek → registry.detectFile → adapter.parse → adapter.normalize → pipeline.buildImportPlan → planToOp
```

Adapters live in `src/import/adapters/` (BNP Paribas, Revolut, PrivatBank, PUMB, Monobank) and
implement the contract in `src/import/types.ts`. Each must be **source-ordered and deterministic**:
parsing the same file twice must produce identical rows and identical hashes, because those hashes
are how re-importing the same statement avoids duplicating it.

Fixtures under `tests/fixtures/` are generated by `scripts/make-fixtures.ts` from real statements
that never enter git. See [CONTRIBUTING.md](../CONTRIBUTING.md#fixtures) before touching them.

## UI

`src/ui/` is React with inline styles and design tokens defined in `index.html`. Routing is
**hash-based** (`src/ui/route.ts`) — the route is the single source of truth, and that is why the
app needs no server rewrite rules to be deep-linkable.

One codebase serves desktop and phone; layout branches on a breakpoint rather than shipping two
trees.

## Dev and test hooks

Query parameters gated behind `import.meta.env.DEV`, compiled out of production builds:

| Hook | Effect |
|---|---|
| `?now=<ISO>` | freezes the clock |
| `?kdf=test` | makes key derivation instant |
| `?remote=test:<name>` | connects the in-memory dev remote |
| `?drive=test:<slot>` | swaps Google's API for a local double |
| `?nofsa` | forces the plain file-input fallback |

The e2e suite depends on these, which is why it runs against the dev server rather than a
production build. Do not "fix" that.
